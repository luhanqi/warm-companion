# 暖伴 1.5B 训练说明

当前流程**只训练 `Qwen/Qwen2.5-1.5B-Instruct`**。以前无显卡时自动改成 0.5B 的逻辑已经去掉。

**不能把 0.5B 的 LoRA 接到 1.5B 上。** 层宽不同，参数对不上。仓库里已有的 `outputs/sft/`、`outputs/sft-v2/`、`outputs/dpo-v2/` 是旧的 0.5B 实验，默认不会再用。1.5B 的产出写到 `outputs/sft-1.5b/`。

---

## 一、需要配置什么

改模型大小、产出目录、学习率，**优先改 `train/config.yaml`**，不必改 Python。命令行参数会覆盖 yaml 里的同名项。

### 1. `train/config.yaml`（必改 / 常改）

| 字段 | 现在的值 | 作用 |
|---|---|---|
| `base_model` | `Qwen/Qwen2.5-1.5B-Instruct` | 底座模型。不要改成 0.5B |
| `sft_output` | `outputs/sft-1.5b` | SFT 产出目录，LoRA 在其中的 `adapter/` |
| `dpo_output` | `outputs/dpo-1.5b` | DPO 产出目录 |
| `merged_output` | `outputs/merged-1.5b` | 合并完整权重的目录 |
| `epochs` | `3` | 监督微调轮数 |
| `learning_rate` | `0.0001` | SFT 学习率 |
| `lora_r` | `16` | LoRA 秩；alpha 固定为 `r * 2` |
| `max_len` | `512` | 单条最长 token |
| `batch` | `1` | 每步样本数 |
| `accum` | `8` | 梯度累积，等效 batch = 8 |

本地已手动下载模型时，把 `base_model` 改成文件夹路径，或训练时加 `--model 本地文件夹`。

### 2. Python 环境（必配，且不要混用后端环境）

| 要配什么 | 说明 |
|---|---|
| `train/.venv` | 用 **Python 3.12** 新建。命令：`py -3.12 -m venv .venv` |
| `train/requirements.txt` | transformers / peft / trl / modelscope 等，**不含 torch** |
| torch 单独装 | 有 NVIDIA 卡：`pip install torch --index-url https://download.pytorch.org/whl/cu124`；只有 CPU：`pip install torch --index-url https://download.pytorch.org/whl/cpu` |

**不要**把 torch 装进 `backend/.venv`。后端是 Python 3.8，只负责暖伴业务。

1.5B LoRA 建议 **8–16GB 显存**。没有 GPU 也能启动训练，但会极慢，且容易内存不够。

### 3. `backend/.env`（只有接到产品时才配）

训完并启动 `python serve.py` 之后，在 `backend/.env` 写：

```
LLM_API_KEY=local
LLM_BASE_URL=http://127.0.0.1:8001/v1
LLM_MODEL=nuanban
```

参考模板：`backend/.env.example`。不填这三项时，后端仍走原来的外部 API / 本地规则陪伴，不影响演示。

### 4. 一般不用改的文件

| 文件 | 为什么通常不动 |
|---|---|
| `train/prompt.py` | 系统提示。若改，必须同步 `backend/app/llm.py` 里的 `SYSTEM_PROMPT` |
| `train/build_seed.py` | 种子对话。要加场景再改这里 |
| `train/requirements.txt` | 缺包再加一行 |

## 二、`train/` 里每个文件干什么

### 配置与环境

| 路径 | 作用 |
|---|---|
| `config.yaml` | 1.5B 模型 ID、产出目录、超参。改训练先改这里 |
| `settings.py` | 读 `config.yaml`，缺字段用 1.5B 默认值；把产出路径变成绝对路径 |
| `requirements.txt` | 训练依赖（不含 torch） |
| `run_train.ps1` | 一键：建 venv、装 CUDA torch（加 `-Cpu` 则装 CPU 版）、制数据、跑 SFT。加 `-Smoke` 只跑几步确认环境 |
| `README.md` | 短步骤。细节以本文为准 |
| `文档.md` | 本文件 |

### 数据

| 路径 | 作用 |
|---|---|
| `prompt.py` | 暖伴系统提示，生成种子和本地试聊都用它 |
| `build_seed.py` | 写出暖伴场景：闲聊、记忆、低落不诊断、拒用药、挂号教学、并行一句出口 |
| `prepare_data.py` | 先跑 `build_seed.py`，再写成 `data/prepared/*.jsonl`。关键句会重复一遍。`--public N` 可再混入 N 条公开中文短指令（需外网） |
| `data/seed_sft.jsonl` | 监督微调种子（由 `build_seed.py` 生成） |
| `data/seed_dpo.jsonl` | 对错对比种子 |
| `data/seed_eval.jsonl` | 规则评测题 |
| `data/prepared/` | 真正喂给训练的 jsonl，可重新生成，不必手改 |

### 训练与导出

| 路径 | 作用 |
|---|---|
| `resolve_model.py` | 解析底座：本地文件夹 → `hf_cache` → ModelScope → Hugging Face |
| `train_sft.py` | LoRA 监督微调。默认读 `config.yaml`。看到模型 ID 里有 `0.5B` 会直接退出。`--continue-from` 只能接同一 1.5B 的 LoRA |
| `train_dpo.py` | 在 SFT 的 LoRA 上再做 DPO，压诊断 / 用药 / 抢话。默认读 `outputs/sft-1.5b/adapter`。0.5B 的 LoRA 会拒绝 |
| `export_merge.py` | 把 LoRA 和底座合成完整权重，方便拷到别的机器 |

### 试聊、评测、接到产品

| 路径 | 作用 |
|---|---|
| `chat.py` | 命令行试聊。默认加载 `outputs/sft-1.5b/adapter` |
| `eval_model.py` | 对照 `data/prepared/eval.jsonl` 做规则检查（必须出现 / 禁止出现某些词） |
| `serve.py` | OpenAI 兼容接口，默认 `127.0.0.1:8001`。暖伴后端把 `LLM_BASE_URL` 指过来即可 |

### 运行时目录（不要当源码改）

| 路径 | 作用 |
|---|---|
| `.venv/` | 训练专用虚拟环境 |
| `hf_cache/` | 底座权重缓存（0.5B / 1.5B 都可能在这里） |
| `outputs/sft-1.5b/` | **当前默认** SFT 产出，`adapter/` 给 chat / serve / eval 用 |
| `outputs/dpo-1.5b/` | DPO 产出（跑过 `train_dpo.py` 才有） |
| `outputs/merged-1.5b/` | 合并后的完整权重 |
| `outputs/sft/`、`sft-v2/`、`dpo-v2/` | 旧 0.5B 实验，**不要** continue-from 到 1.5B |
| `__pycache__/` | Python 缓存 |

## 三、推荐命令（有 NVIDIA 卡）

在 `train/` 下，先激活训练环境：

```powershell
cd train
.\.venv\Scripts\Activate.ps1
```

第一次：

```powershell
.\run_train.ps1
```

或逐步：

```powershell
python prepare_data.py
python train_sft.py
python eval_model.py
python chat.py --text "今天中午吃了面"
```

可选 DPO（建议先用 SFT 试聊，确认效果再决定是否做；上一版 0.5B 的 DPO 质量变差，不要直接接到产品）：

```powershell
python train_dpo.py
python chat.py --adapter outputs/dpo-1.5b/adapter --text "今天中午吃了面"
```

接到暖伴：另开终端 `python serve.py`，再按上文改 `backend/.env`。

页面不会直接加载模型。链路是：

浏览器（5173）→ Vite 把 `/api` 转到后端（8000）→ 陪伴智能体 `stream_reply` → `backend/app/llm.py` 按 `.env` 去请求 `http://127.0.0.1:8001/v1/chat/completions` → `train/serve.py` 加载 `outputs/sft-1.5b/adapter` 流式吐字。

因此要同时开三个进程：`python serve.py`（模型）、`npm run server`（后端）、`npm run dev`（页面）。本地 1.5B 不做 JSON 抽取，记忆仍走规则提取。

只有 CPU、只想确认脚本能跑时：

```powershell
.\run_train.ps1 -Cpu -Smoke
```

## 四、和 0.5B 的关系

| 可以 | 不可以 |
|---|---|
| 保留旧的 `outputs/sft/` 当对照 | `--continue-from outputs/sft/adapter` 接到 1.5B |
| 手动 `python chat.py --adapter outputs/sft/adapter` 试旧模型 | 把 `config.yaml` 的 `base_model` 改回 0.5B 当「正式流程」 |
| 1.5B 训完自己再 `--continue-from outputs/sft-1.5b/adapter` | 把 0.5B DPO 接到产品当默认 |

显卡 24GB 以上若要试 3B，改 `config.yaml` 的 `base_model` 为 `Qwen/Qwen2.5-3B-Instruct`，并同步改 `sft_output` 以免覆盖 1.5B 权重。
